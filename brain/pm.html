内部交接 · 产品简报

Page2Reading

把网页上的英文技术文章，变成每周可以装订的纸。点一下就走，人不用盯着翻译和导出。

本地优先 · Chrome 扩展 + Mac 服务 不是云笔记，不是全文阅读器

你要先接受的三句话

用户是谁 习惯纸质阅读的技术学习者。每周或每两周打印一批博客 / 文字稿，装订后像看报纸一样每天一篇。
解决什么 以前：复制原文 → 免费网页翻译 → 再导出，人被绑在屏幕前。现在：文章页点一下，后台出 PDF，飞书留台账。
明确不做什么 不做云账号、不做 App 商店分发、不做手机端、不把图片另存、不上传 PDF 到飞书。飞书只记路径。

产品形态

用户感知是「Chrome 里两个按钮」。实际是两段：扩展只采集当前页；本机服务负责抽取、翻译、排版、写桌面、记飞书。没有本机服务，扩展什么都写不出来。

1打开文章点扩展
2选原文或中英对照
3立刻可关页面
4桌面按日期出文件
5飞书多维表格记账

两个能力，不要合并成一个开关糊弄过去

导出原文 PDF 清洗正文，保留标题、作者、日期、链接、代码、表格、远程图片。
文件：or-标题.md + or-标题.pdf
导出中英对照 PDF 段落级对照，口语讲解风（不是公文翻译）。对照模式仍保留原文 Markdown。
文件：or-标题.md + tr-标题.md + tr-标题.pdf

PDF 文末才放元数据和来源二维码，正文从第一段直接开始读。图片不下载到本地，印进 PDF 时现拉。

文件和台账怎么算「做对了」

~/Desktop/Page2Reading/
└── 20260911/
    ├── or-....md / .pdf
    └── tr-....md / .pdf

飞书 7 列必须全是文本，名字不能改：标题、原文链接、作者、文章发布日期、收录时间、PDF 文件、Markdown 文件。后两个中间有空格。不存附件。

同一篇文章的原文和对照会写进同一条飞书记录（按原文链接），后写覆盖。未配飞书时本地文件仍算成功。

范围边界（评审时用）

做
  • 英文技术博客 / 文字稿
  • Mac + Chrome
  • DeepSeek 翻译（默认 Flash，关 thinking）
  • A4 可打印 PDF
  • 失败可重试
不做（当前版本）
  • 菜单栏 App / 商店一键安装
  • Windows / 手机
  • RSS 订阅、批量打印装订线
  • 账号体系、云端渲染
  • 把密钥放进扩展

已知问题和产品债

问题对用户的影响优先级
必须先开本地服务忘了启动就点不出东西P1 体验
扩展未上架，要加载 dist别人用不了「开箱」P2 分发
扩展没有「强制重跑」同一链接默认不重复导出P2
部分站点图片防盗链PDF 可能缺图，状态为 succeeded_with_warningsP3
飞书列名稍错即失败本地已出 PDF，台账没有已可重试补同步

建议路线（和研发对齐用）

  1. 基建：测试、CI、仓库规范。
  2. 健壮：失败自动退避；HTML 改存文件；库清理。
  3. 能力：更多模型、Obsidian 目录、批量 URL。
  4. 分发：打包扩展 + 安装脚本。产品已否决「再做一个菜单栏 App」。

验收清单

  • 英文博客页：原文 PDF 能出，桌面日期目录正确
  • 对照 PDF：一段英一段中，文末有链接和二维码
  • 提交后关掉标签页，任务仍能完成
  • 飞书七列有记录，路径能对上文件
  • 飞书故意写错列名时本地文件还在，修好后重试只补表
  • 未配飞书时仍能成功，只是提示跳过台账
