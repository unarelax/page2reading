Page2Reading 问题记录

导出链路上遇到的坑，和已经落到代码里的处理。新问题补在最上面。改完扩展要在 chrome://extensions 重新加载，浏览器跑的是 apps/extension/dist/。

最近更新 2026-09-24

导出实际在做什么

Markdown 和 PDF 不是同一步。offscreen 文档先抽取正文（对照模式再分段翻译），把 .md 写进选定目录，然后才排版 PDF。

  1. markdown-it 把正文变成带 style.css 的 HTML。
  2. HTML 放进 chrome.storage.session，打开一个不激活的隐藏标签页画出来，并等远程图片。
  3. Service Worker 用 chrome.debugger 只附在这个隐藏页上，调用 Page.printToPDF。
  4. PDF 按块解码，offscreen 文档用目录句柄逐块写入 .pdf。写完一块，再读下一块。

扩展没有后台，也不能起本地进程，所以没有「把 md 交给一个库、拿回 pdf」这一步。版式靠 Chrome 的打印引擎，才能用系统里的中文字体、A4 和现有样式。

已处理

PDF 生成出来是 0KB

2026-09-24

现象。导出跑完，目录里有 PDF，大小是 0 字节。

原因。扩展端口不能可靠传递 Uint8Array，二进制块到 offscreen 后不再是字节数组，byteLength 是空的。写入流因此写进 0 字节，又因为空长度不是数字 0，空文件检查被绕过，文件仍被正常关闭。getFileHandle 一创建就会在磁盘上留下这个空文件。另外，把 ArrayBuffer 直接交给 writable.write 时，浏览器会把它当成写入参数对象，同样写不出内容。

处理。每一块先编成 base64 字符串再传。写入用 Blob。关闭后读一次真实文件大小，仍是 0 就删掉并报错。中途失败也删掉这个占位文件。

长文 PDF 整包传回，导出失败，浏览器发沉

2026-09-24

现象。篇幅很长的 Markdown 很快就在目录里，PDF 一直没有。导出过程中整个 Chrome 变重。

原因。打印结果先被拼成一整段 base64，经扩展端口再拷一份，offscreen 里再用 atob 解成字节。同一份文件在内存里同时有两三份。更早一版用 ReturnAsBase64，单条调试器消息装不下，sendCommand 的回调永远不回来，任务像卡死。

处理。调试器侧改为 ReturnAsStream，按大约 2MB 一块读取。每块解码后发给 offscreen，写入确认之后才读下一块。失败时 abort 丢掉临时文件，不留下半份 PDF。Service Worker 不能对用户选定的目录调用 createWritable（会报当前上下文不允许），所以文件仍由 offscreen 文档写，它本来就拿着 IndexedDB 里的目录句柄。

打印那几秒到几十秒的 CPU 还在，那是排版和嵌图。隐藏页关掉后释放。内存里不再同时躺着整份 PDF。

按偏移读 PDF 流会跳字节；空块被当成结束

2026-09-24

现象。流式读取若自己累加 offset，Chrome 某次返回的字节数少于请求的大小时，下一次会跳过中间一段，PDF 损坏。空数据且还没到结尾时如果直接停，文件会被截断。

处理。IO.read 不再传 offset，顺着流往下读。结束前遇到空数据就报错，不把残缺内容当成成功。base64 可能在 4 字符边界被切开，不足 4 字符的尾巴留给下一块，最后一块再补 =。

分块写入失败后，任务既不成功也不失败

2026-09-24

现象。某一块写入失败后，错误处理挂在已经拒绝的 Promise 的 then 上，回调不会跑。临时文件不丢弃，导出 Promise 也不结束。

处理。失败先回一条带错误的确认，让 Service Worker 停下来。随后的失败收尾用 catch 再 abort 写流，并把任务标成失败。确认回调里不再把错误抛回去，避免这条链变成未处理拒绝。

Uint8Array 不能直接交给文件写入流

2026-09-24

现象。类型检查报 Uint8Array<ArrayBufferLike> 不能赋给 FileSystemWritableFileStream.write。

处理。每块先拷进一块新的 ArrayBuffer，再包成 Blob 写入。不能把 ArrayBuffer 直接交给 write，见上面的「0KB」。

长文对照导出成功，文件里几乎只有中文

2026-09-22

现象。tr-How-to-Get-Rich.md 和对应 PDF 都生成了，但正文几乎全是中文。短文以前可以中英对照。

原因。短文整篇一次送进模型，提示词要求段落级对照。长文拆成二十多段之后，每段的提示写成「只翻译这一段正文」。模型只交回中文，英文没有从原文拼回去。校验也不看原文还在不在，所以纯中文译文仍标成成功。

处理。英文段落由程序从原文留下，模型只出对应中文，再按「一段英文、一段中文」交错写入 Markdown 和 PDF。已经落盘的纯中文文件不会自动变对照，需要重新导出。

长文对照被 6 分钟总超时掐掉，弹窗却一直「导出中」

2026-09-22

现象。浏览器开着，Service Worker 也没被回收，日志里没有 request-pdf。任务在翻译阶段失败，文案像是在说浏览器被关掉。弹窗顶栏不改成真正的错误。

原因。像 Naval《How to Get Rich》这种约 50 个小节的文章，会拆成二十多段逐段调 DeepSeek，墙钟经常超过 6 分钟。控制台还会把两条相同的 progress 折成一行，看起来像只走了一步。

处理。取消 6 分钟总超时。连续 5 分钟完全没有进度才中止；整篇硬上限 90 分钟。每开始一次请求、每译完一段都刷新进度，弹窗显示「翻译中 3/26」。结束后写出失败原因。超长文不再做整篇重译，那一次额外请求本身就容易再卡死。

Service Worker 重启后，旧的 offscreen 端口把队列卡死

2026-09-22

现象。扩展后台被回收再起来，内存里的管道状态没了，但旧的 offscreen 文档还在。新任务投递不进去，或者 render-ready 到达时 pendingPdf 已经是空的，这条消息被丢掉，任务停在「生成 PDF」，直到无进度超时。

处理。每个任务开始前关掉并新建 offscreen 文档，不复用重启前留下的端口。日志里若出现「pendingPdf 为空或 taskId 不匹配」，就是隐藏页准备好了、但后台已经不记得这个任务。

保存目录的权限弹窗不能从后台弹出

现象。上次授权失效后，导出直接失败，后台里调用 requestPermission 也不会出现系统对话框。

处理。权限不是 granted 时直接报错，提示打开扩展设置页点「重新授权」或重新选目录。选目录必须发生在设置页的用户点击里。

还在，但不要当成导出坏了

  • Chrome 会提示「扩展正在调试此浏览器」。调试器只附在自己打开的隐藏渲染页上，不附在正在读的文章页。
  • Markdown 里的图片只是 URL。PDF 必须在隐藏页里把图下载下来嵌进去，总等待大约 15 秒。没加载上的图记成「完成（缺图）」，正文照样导出。
  • 目录里已经有 .md、还没有 .pdf，表示正文写完了，打印还在进行或打印失败。看弹窗是「生成 PDF」还是具体错误。
  • Page.printToPDF 单次命令上限 180 秒，每一块落盘的确认上限 60 秒。超过就失败，可以重试。
