导出实际在做什么

对照或原文写出 .md，主任务就算成功。短文（原文正文不超过约 3 万字）再走隐藏页 + Page.printToPDF 写出 .pdf。对照也按原文长度判断，不按对照稿翻倍后的字数。长文跳过 PDF。图只是链接，张数不限制。不再写 .html。

PDF 失败或跳过只记警告，不会把已经写好的 Markdown 标成失败。

已处理

对照卡在 0/6，PDF 没有标题、链接和二维码

2026-09-28

现象。弹窗一直显示「翻译中 0/6 第 1 组」。已经生成的 PDF 看不到原文标题、链接和文末二维码。

原因。第 1 组请求没结束前进度不更新，看起来像卡住。Chrome 打印页把 header/footer 当成页眉页脚，再叠加 displayHeaderFooter，文首标题和文末二维码会被盖住。文末用 flex、二维码用 SVG，打印时也经常丢。

处理。进度改成「第 1/6 组 · 请求中」，每次请求结束才续闲置计时。Markdown 转 PDF 会读 YAML 的 title/source，把标题和原文链接放在文首，文末再放链接和 PNG 二维码。扩展和本地 build_pdf.mjs 都这样处理。不再用 header/footer 标签。

标题没译成中文会把整篇对照判失败

2026-09-28

现象。导出 The UN challenges five centuries of cartography 时报「第 1 块不像中文译文」。

原因。模型常把英文标题原样送回。校验要求超过约 24 字就必须有汉字。失败后把整组对半拆，标题单独成块仍然没有汉字，整篇对照失败，Markdown 也不写。

处理。对半拆只用于编号/格式失败。某一块没有汉字时，先保住已经译好的块，只重试失败的那些；仍没有汉字就保留英文，继续译后面，不再整篇失败。

短文门槛从 2 万调到 3 万

2026-09-28

处理。仍只看原文正文。不超过约 3 万字视为短文，对照和原文都会打 PDF。按当前版式大约十到二十多页 A4。

导出的 PDF 里有很多横线

2026-09-27

现象。PDF 每页上下、每个二级标题下面都有横线，对照稿更明显。

原因。撑页边距的隐藏表和正文表格共用 td { border }，表头表尾每页重复，就变成页眉页脚横线。二级标题又画了底边，中英各一条。

处理。隐藏表去掉边框。格子线只留给正文里的表格。二级标题不再画底边。

长文对照越译越书面，表格还留着英文

2026-09-27

现象。分段翻译后半段容易退化成直译；Markdown 表格中英各留一张，读着重复。

处理。按 ## 章节打包（每组 1–3 节，仍受单次请求字数上限约束，避免再卡死）。第一段抽出最多 3 条风格锚点，后面各组沿用，不再每组覆盖。一组若明显偏书面（赋能/闭环/本质上/鉴于）会再译一次。表格只保留中文表。图片仍是链接，接在该段中文后面。全文拼完后对比前后半段口语词频，只打日志，不再整篇重译。

短文门槛按打印稿字数，对照会被误判成长文

2026-09-27

现象。原文不到 2 万字的文章（例如 Claude 那篇现代化指南约 1.9 万字）对照导出后没有 PDF。原先按拿去打印的 Markdown 计，门槛约 1.2 万字，对照稿大约是原文两倍，很容易超。

处理。只看原文正文。不超过约 2 万字视为短文，对照和原文都会打 PDF。

对照翻译可以空转一个小时还不结束

2026-09-26

现象。弹窗一直显示「翻译中」，过了一个小时还没有 Markdown。

原因。某一组格式不对或接口变慢时，会多次重试再对半拆开继续请求。每次请求开始都会刷新「5 分钟无进度」计时，整篇又有 90 分钟总上限，所以能空转很久。弹窗只在整组完成后才更新段数，看起来像卡住。

处理。时间上限收紧并真正生效：单次请求 45 秒；只有译完一组、写出文件或 PDF 分块才续时，连续 4 分钟没有这类进度就停；对照翻译最多 12 分钟；整篇最多 18 分钟。重试开始不再刷新计时。

长文 PDF 失败会把整篇导出标成失败

2026-09-26

现象。对照 Markdown 已经写好，PDF 一卡，弹窗仍像整篇没完成。

处理。.md 写完即成功。短文才打 PDF；原文正文超过约 3 万字就跳过。图只是链接，不按张数限制。PDF 失败只作为警告。不再写 .html。

打印出来的 PDF 四边没有边距

2026-09-25

现象。How To Be Successful - Sam Altman.pdf 是 A4，但正文从纸边开始，左边距和上边距都是 0。

原因。打印对话框里的「边距：无」会盖掉 CSS 的 @page 边距。body 的内边距又只在第一页和最后一页有效，中间页仍然顶边。

处理。用每页都会重复的表头、表尾留出上下约 16mm，单元格左右留出 18mm。这样对话框边距是「无」时，字也不会贴边。

点「导出 PDF」后版式很差

2026-09-25

现象。阅读页本身正常，一进打印对话框，页面发黑、字发灰，中英段落挤在一起，两端对齐把行距拉开。

原因。打印没用屏幕那套样式。浏览器若处于深色外观，没声明 color-scheme: light 时会把白底印成黑底。正文又继承了 text-align: justify。

处理。打印强制白底深字、左对齐，英文和中文之间留出一小段间距。页码仍在页脚。

长文自动转 PDF 让电脑发热、浏览器卡顿

2026-09-25

现象。篇幅一长，导出总在转 PDF 上失败或拖很久，电脑发热，浏览器明显卡。

处理。导出改为同时写 .md 和 .html。HTML 在浏览器里阅读；PDF 改到阅读页上的按钮，走系统打印对话框，页脚是当前页/总页数。不点打印，就不会做分页和嵌图。

PDF 生成出来是 0KB

2026-09-24

现象。导出跑完，目录里有 PDF，大小是 0 字节。

原因。扩展端口不能可靠传递 Uint8Array，二进制块到 offscreen 后不再是字节数组，byteLength 是空的。写入流因此写进 0 字节，又因为空长度不是数字 0，空文件检查被绕过，文件仍被正常关闭。getFileHandle 一创建就会在磁盘上留下这个空文件。另外，把 ArrayBuffer 直接交给 writable.write 时，浏览器会把它当成写入参数对象，同样写不出内容。

处理。每一块先编成 base64 字符串再传。写入用 Blob。关闭后读一次真实文件大小，仍是 0 就删掉并报错。中途失败也删掉这个占位文件。

长文 PDF 整包传回，导出失败，浏览器发沉

2026-09-24

现象。篇幅很长的 Markdown 很快就在目录里，PDF 一直没有。导出过程中整个 Chrome 变重。

原因。打印结果先被拼成一整段 base64，经扩展端口再拷一份，offscreen 里再用 atob 解成字节。同一份文件在内存里同时有两三份。更早一版用 ReturnAsBase64，单条调试器消息装不下，sendCommand 的回调永远不回来，任务像卡死。

处理。调试器侧改为 ReturnAsStream，按大约 2MB 一块读取。每块解码后发给 offscreen，写入确认之后才读下一块。失败时 abort 丢掉临时文件，不留下半份 PDF。Service Worker 不能对用户选定的目录调用 createWritable（会报当前上下文不允许），所以文件仍由 offscreen 文档写，它本来就拿着 IndexedDB 里的目录句柄。

打印那几秒到几十秒的 CPU 还在，那是排版和嵌图。隐藏页关掉后释放。内存里不再同时躺着整份 PDF。

按偏移读 PDF 流会跳字节；空块被当成结束

2026-09-24

现象。流式读取若自己累加 offset，Chrome 某次返回的字节数少于请求的大小时，下一次会跳过中间一段，PDF 损坏。空数据且还没到结尾时如果直接停，文件会被截断。

处理。IO.read 不再传 offset，顺着流往下读。结束前遇到空数据就报错，不把残缺内容当成成功。base64 可能在 4 字符边界被切开，不足 4 字符的尾巴留给下一块，最后一块再补 =。

分块写入失败后，任务既不成功也不失败

2026-09-24

现象。某一块写入失败后，错误处理挂在已经拒绝的 Promise 的 then 上，回调不会跑。临时文件不丢弃，导出 Promise 也不结束。

处理。失败先回一条带错误的确认，让 Service Worker 停下来。随后的失败收尾用 catch 再 abort 写流，并把任务标成失败。确认回调里不再把错误抛回去，避免这条链变成未处理拒绝。

Uint8Array 不能直接交给文件写入流

2026-09-24

现象。类型检查报 Uint8Array<ArrayBufferLike> 不能赋给 FileSystemWritableFileStream.write。

处理。每块先拷进一块新的 ArrayBuffer，再包成 Blob 写入。不能把 ArrayBuffer 直接交给 write，见上面的「0KB」。

长文对照导出成功，文件里几乎只有中文

2026-09-22

现象。tr-How-to-Get-Rich.md 和对应 PDF 都生成了，但正文几乎全是中文。短文以前可以中英对照。

原因。短文整篇一次送进模型，提示词要求段落级对照。长文拆成二十多段之后，每段的提示写成「只翻译这一段正文」。模型只交回中文，英文没有从原文拼回去。校验也不看原文还在不在，所以纯中文译文仍标成成功。

处理。英文段落由程序从原文留下，模型只出对应中文，再按「一段英文、一段中文」交错写入 Markdown 和 PDF。已经落盘的纯中文文件不会自动变对照，需要重新导出。

长文对照被 6 分钟总超时掐掉，弹窗却一直「导出中」

2026-09-22

现象。浏览器开着，Service Worker 也没被回收，日志里没有 request-pdf。任务在翻译阶段失败，文案像是在说浏览器被关掉。弹窗顶栏不改成真正的错误。

原因。像 Naval《How to Get Rich》这种约 50 个小节的文章，会拆成二十多段逐段调 DeepSeek，墙钟经常超过 6 分钟。控制台还会把两条相同的 progress 折成一行，看起来像只走了一步。

处理。取消 6 分钟总超时。连续 5 分钟完全没有进度才中止；整篇硬上限 90 分钟。每开始一次请求、每译完一段都刷新进度，弹窗显示「翻译中 3/26」。结束后写出失败原因。超长文不再做整篇重译，那一次额外请求本身就容易再卡死。

Service Worker 重启后，旧的 offscreen 端口把队列卡死

2026-09-22

现象。扩展后台被回收再起来，内存里的管道状态没了，但旧的 offscreen 文档还在。新任务投递不进去，或者 render-ready 到达时 pendingPdf 已经是空的，这条消息被丢掉，任务停在「生成 PDF」，直到无进度超时。

处理。每个任务开始前关掉并新建 offscreen 文档，不复用重启前留下的端口。日志里若出现「pendingPdf 为空或 taskId 不匹配」，就是隐藏页准备好了、但后台已经不记得这个任务。

保存目录的权限弹窗不能从后台弹出

现象。上次授权失效后，导出直接失败，后台里调用 requestPermission 也不会出现系统对话框。

处理。权限不是 granted 时直接报错，提示打开扩展设置页点「重新授权」或重新选目录。选目录必须发生在设置页的用户点击里。

还在，但不要当成导出坏了

  • 短文 PDF 仍走隐藏页打印。图是原文链接，加载失败会标成「完成（缺图）」，Markdown 不受影响。
  • 长文目录里只有 .md 是预期行为，不是导出坏了。
